# Architecture — AHC Video Anomaly Detection

## Shipped system

The submitted system runs entirely locally on a 6 GB RTX 4050. It uses a frozen SigLIP2 vision encoder at 2 fps and a trained ClipHead. The day-of entry point consumes the delivered manifest and MP4 files, builds a resumable embedding cache, predicts every video, attaches a deterministic explanation, and validates the resulting JSON.

```
MP4 + manifest
  → decode/sample at 2 fps → frozen SigLIP2 → cached embeddings
  ├─ level 1: ClipHead on the full clip → one class or no event
  └─ levels 2/3: ClipHead on overlapping windows → merge same-class evidence
       → changepoint-snap interval edges → expand → scored event JSON
```

The encoder and ClipHead are local at runtime. There are no hosted-model calls in the inference or explanation paths.

## Trained components and decoder

`ClipHead` is an attention-pooling 12-way classifier (11 anomaly classes plus normal) trained on frozen embeddings. Class weights use inverse square-root frequency to reduce the imbalance between traffic accidents and tail classes. At level 1 it runs once on the complete clip. At levels 2 and 3 it supplies local evidence from overlapping windows.

The production L2/L3 decoder uses 3 s windows, a 1 s stride, a 0.4 threshold, same-class merging, 1.25x centre expansion, and endpoint snapping to nearby embedding changepoints. Events retain their window confidence and receive a valid template explanation.

## Measured public-dev result

The public 34-video dev result is **48.20/100**: D1 18.23, D2 21.97, D3 8.00. It is robust across the scorer sensitivity grid: minimum 48.20, median 50.49, maximum 54.49.

L2 finds 5 of 18 events. T028 is a clean 4/4 with matched IoUs 0.87, 0.67, 0.64, and 0.67. The result is generated by `python -m ahc.predict`, not a hand-edited submission.

The changepoint ablation holds window, stride, threshold, and expansion fixed. Removing snap reduces the grid minimum from 48.20 to 46.56 (**−1.64**), so snapping remains enabled.

## Runtime measurement

A full public-pack rehearsal begins from MP4 files and produces a validated submission in 88.36 s for 3,391.36 s of video: **RTF 0.0261**. This timing includes decoding, preprocessing, frozen-encoder inference, head inference, and post-processing. It excludes only model loading and downloads. Median full-path time is 216.59 ms per video; the longest clip, T033 (629 s), took 20.1 s.

## Experiments not shipped

1. **Synthetic-splice temporal head.** A convolution/transformer temporal head was trained on synthetic spliced embedding sequences. It did not pass the held-out real long-video gate: precision was 0.39%, recall 5.8%, and false alarms occurred on 39.3% of normal videos. It is therefore not used in `predict.py`.

2. **Full-interval reclassification.** Local windows were merged regardless of their local class, then reclassified with ClipHead on the complete interval to test whether the 3 s window caused T025's class errors. This scored 45.46 on the grid minimum and still preferred wrong-way/blocking labels; it is opt-in and disabled.

An L3-only 768-configuration search over 6–24 s windows, stride, threshold, expansion, gap bridging, caps, and a 60% span guard found no improvement. The best setting only reproduced the 48.20 baseline, while the remaining top candidates fell to 40.20 or lower. This is a genuine limitation of absolute appearance thresholding for duration/change anomalies, not a shipped tuning gain.

## Limitations and next work

The main weakness is L3: appearance may be common across a video even though the anomaly is relative to duration or scene context. Per-video robust normalization of each class-score curve is the next controlled experiment; it must beat the grid minimum before adoption. T025's localized but misclassified accidents point separately to class discrimination, not a localization error.
